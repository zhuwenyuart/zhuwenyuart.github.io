# 作品 CMS 与图片

## CMS 管理范围

根目录 `.pages.yml` 只提供：

- 作品编辑：`docs/artwork.json`，数组和现有字段保留。
- 作品图片：`docs/media/artworks/`，输出地址 `/media/artworks`。

`docs/media/site/`、`docs/media/brand/` 采用同一个 GitHub 存储／发布方式，但不开放 CMS 编辑入口。App 自身的仓库权限与界面范围不是一回事，安装时仍需审查授权。

## 已有用户切换

合并这次改动并按 [部署说明](deployment.md) 把 Pages 改为 main 的 `/docs` 后，在 Pages CMS 重新打开仓库／main，确认它加载新配置。不要继续用旧会话保存到 `content/artwork.json` 或 `public/media/artworks/`；它们已经不是维护来源。

当前所有已保存作品，包括“实习生”，都迁入 `docs/artwork.json`，图片地址没有改变。

## 上传与更新

1. 打开 [app.pagescms.org](https://app.pagescms.org)，选择原仓库及 main。
2. 进入作品管理，新增或编辑列表项。
3. 在图片字段上传或选择一张作品图，填写名称、四位年份、系列、材料、尺寸。
4. 保存作品资料。上传图片和保存资料可能是两个提交，只上传不生成作品。
5. 等待 GitHub Pages 分支发布完成，刷新正式站查看。不再编译或手动点 Deploy。

第一次安装仍需仓库所有者登录 GitHub、安装 Pages CMS App、只授权这个仓库。已授权用户通常无需重新安装，仅需重新读取配置。不要向聊天或仓库提交 token、密码、私钥。

## 删除

- 删除作品：移除作品列表中的那个项并保存，不要删整个 artwork.json。
- 删除图：先移除或替换所有主图／细节图引用并保存，再从媒体库删文件。
- 移除作品记录不会自动删图片，以免误删其他引用。
- 已删除文件可能仍存在 Git 历史，删除不能当成隐私擦除。

## 存储约定

```text
docs/media/
├── artworks/    公开作品图，CMS 管理
├── site/        网站照片／配图，手工管理
└── brand/       Logo、社交图标，手工管理
```

无压缩、裁切或缩略图生成。网站用图只维护一份。第三方资源保留在 docs 的原相对路径，原图仍在仓库根的 `image_origin/`，不属于公开站点目录；但公开仓库和历史里仍能访问原图。

所有 docs 图片都可能按地址访问，未被作品列表引用不代表私密。不把未经允许公开的照片、原图或私人资料上传到这里。

## 校验和取舍

- CMS 表单有必填、图片扩展名和年份提示，浏览器用安全文本节点与作品路径白名单处理数据。
- 本项目已经移除自动 Actions 检查，不能把图片上限或完整解码称为上传时的强制限制。
- 可选本地 `npm run check` 仍可检查文件解码、真实扩展名、5 MiB、2400 万像素、单边 8000 像素与缺失引用。它不修改文件、不构建，也不发布。
- 此前 6 件作品引用的 12 张细节照片未放入网站图片库；本次从 `image_origin/` 按原路径逐字节复制到 `docs/media/artworks/`，原图库未改，缺图引用已全部补齐。CMS 可列出／选择这些文件；公开弹窗仍不展示说明／细节图，未扩展新展示功能。
- 正常内容更新无需调整测试。数据规则和核心交互变更时，可选运行轻量测试。

取消自定义 Actions 后，“只操作 CMS”的代价是没有发布前自动质量门槛。若保存错误内容，直接修正记录／图片即可，不要恢复编译流程来满足本次需求。
